# 《玉简问道 · PathOfJade》服务端部署与运维备忘

本文档记录 CentOS 服务器上 `jade-server` 的环境变量配置（尤其是移除硬编码默认密钥后的 JWT 密钥配置）、常规更新部署流程以及常用运维命令。

## 一、服务器环境概览

| 项目 | 配置路径 / 参数 |
| :--- | :--- |
| 服务端二进制 | `/opt/jade/jade-server` |
| SQLite 数据库 | `/opt/jade/data/jade.db` |
| Systemd 服务文件 | `/etc/systemd/system/jade-server.service` |
| 服务端本地监听 | `127.0.0.1:28473` |
| Nginx 反代配置 | `/etc/nginx/conf.d/jade.conf` |
| 对外 HTTPS 入口 | `https://allplayer.cn:28474` |

## 二、JWT 密钥环境变量配置（更新去硬编码版本必做）

`server/main.go` 移除默认开发密钥后，服务端启动时强制要求通过环境变量提供 JWT 密钥，未设置时会直接报错退出。

> **确认变量名**：配置前先核对 `server/main.go` 第 65 行实际读取的环境变量名（通常为 `JADE_JWT_SECRET`）。

### 1. 检查现有配置

```bash
cat /etc/systemd/system/jade-server.service
```

查看 `[Service]` 段是否已配置 `JADE_JWT_SECRET`（与 `JADE_ADMIN_KEY` 同级）。若已配置且非旧开发默认字符串，可跳过第 2 步。

### 2. 生成 32 字节随机强密钥

```bash
openssl rand -hex 32
```

复制输出的 64 位随机十六进制字符串。

### 3. 写入 systemd 服务文件

```bash
vi /etc/systemd/system/jade-server.service
```

在 `[Service]` 段中补充环境变量（将变量名与你的 `server/main.go` 保持一致）：

```ini
[Service]
Environment="JADE_JWT_SECRET=替换为刚才生成的64位随机字符串"
Environment="JADE_ADMIN_KEY=已有的管理员密令"
```

### 4. 重载配置并重启服务

```bash
systemctl daemon-reload
systemctl restart jade-server
systemctl status jade-server
journalctl -u jade-server -n 20 --no-pager
```

确认日志中服务正常启动并监听 `:28473`，无缺失环境变量报错即可。

## 三、服务端常规更新部署流程

### 1. 本地交叉编译 Linux 二进制

在本地项目 `server/` 目录下执行（PowerShell 示例）：

```powershell
$env:GOOS="linux"
$env:GOARCH="amd64"
$env:CGO_ENABLED="0"
go build -o dist/jade-server .
```

### 2. 备份并替换服务器二进制

将 `dist/jade-server` 上传至服务器后执行：

```bash
# 停止服务
systemctl stop jade-server

# 备份当前二进制与数据库
cp /opt/jade/jade-server /opt/jade/jade-server.bak.$(date +%Y%m%d%H%M)
cp /opt/jade/data/jade.db /opt/jade/data/jade.db.bak.$(date +%Y%m%d%H%M)

# 替换新二进制并赋权
mv /tmp/jade-server /opt/jade/jade-server
chmod +x /opt/jade/jade-server

# 启动并验证
systemctl start jade-server
systemctl status jade-server
journalctl -u jade-server -n 30 --no-pager
```

## 四、常用运维与排查命令

| 用途 | 命令 |
| :--- | :--- |
| 查看服务状态 | `systemctl status jade-server` |
| 实时查看服务端日志 | `journalctl -u jade-server -f` |
| 查看最近 50 行日志 | `journalctl -u jade-server -n 50 --no-pager` |
| 测试 Nginx 配置并重载 | `nginx -t && systemctl reload nginx` |
| 检查本地端口监听 | `ss -tlnp \| grep -E '28473\|28474'` |
| 测试 HTTPS 接口连通性 | `curl -I https://allplayer.cn:28474/api/health` |

## 五、注意事项

- **更换 JWT 密钥的影响**：更换为新的随机密钥并重启后，之前由旧密钥签发的 30 天免密登录凭证会失效；客户端重新输入一次道号和密令即可恢复，账号与云端存档数据完全不受影响。
- **严禁提交敏感信息**：切勿将 `JADE_JWT_SECRET`、`JADE_ADMIN_KEY`、`jade.db`、`.env`、SSL 私钥或 `jade-server` 编译产物提交到 GitHub 仓库。
- **备份留存**：每次涉及数据库结构迁移的服务端更新前，务必先执行 `jade.db` 备份。
