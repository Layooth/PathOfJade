## 1. 层数机制与妖魔成长公式

### 1.1 是否无尽

镇魔塔为**无尽递增**，没有固定最大层。

依据：

- `DataRegistry.gd:1386`：注释明确「塔层无限递增」
- `GameState.gd:1451-1452`：当前最大可选层 = `tower_highest_floor + 1`
- `CombatEngine.gd:442-448`：胜利后自动排程下一层

### 1.2 妖魔属性公式

普通层：

```text
气血 = round(220 × 1.095^(层数 - 1))
攻击 = round(16 × 1.08^(层数 - 1))
防御 = round(5 × 1.075^(层数 - 1))
攻击间隔 = 2.5 秒
命中 = 0.9
闪避 = 0
```

每 5 层为妖王层，先按普通公式生成，再乘：

```text
气血 × 1.5
攻击 × 1.2
防御 × 1.15
```

命中与闪避来自 `EnemyData` 默认值，镇魔塔动态生成未覆写：

```text
命中 = 0.9
闪避 = 0
```

对应位置：

- `DataRegistry.gd:2768-2800`
- `core/resources/EnemyData.gd:13-14`

### 1.3 战斗结算公式

玩家攻击：

```text
伤害 = max(1, round(攻击 × 随机[0.85, 1.15] - 敌防御 × 0.6))
```

敌人攻击：

```text
伤害 = max(1, round(敌攻击 × 随机[0.85, 1.15] - 玩家防御 × 0.6))
```

随后依次经过：

```text
护符减伤（最高 0.91，战斗内夹到 0.9）
全局减伤（功法 + 本命 + 五行 + 灵根，夹到 0.5）
```

对应位置：

- `GameFormulas.gd:464-471`
- `CombatEngine.gd:300-361`
- `GameState.gd:1170-1175`

## 2. 奖励设计全貌

### 2.1 每层首通奖励

公式：

```text
妖王倍率 = 层数 % 5 == 0 ? 2 : 1

灵石 = 50 × 层数 × 妖王倍率
贡献 = (10 + 层数) × 妖王倍率
```

对应位置：

- `CombatEngine.gd:424-439`
- `GameState.gd:1471-1486`
- `TowerPanel.gd:461-467`

### 2.2 为什么第 127 层是 6350 灵石与 137 贡献

127 不是 5 的倍数：

```text
妖王倍率 = 1
灵石 = 50 × 127 = 6350
贡献 = 10 + 127 = 137
```

因此当前显示完全符合公式。

作为对照，第 130 层是妖王层：

```text
灵石 = 50 × 130 × 2 = 13000
贡献 = (10 + 130) × 2 = 280
```

### 2.3 每 5 层 / 10 层里程碑奖励

真正可见的里程碑写在 `CombatEngine._grant_tower_milestone()`：

- 每 5 层首通本身已通过首通公式的 `×2` 体现
- 每 10 层（偶数节点）：

```text
百年朱果 ×1
聚灵甘露 ×2
```

- 每 5 层但非 10 层（奇数节点）：

```text
仙盟贡献 = 20 + 层数 × 2
随机 2 种品阶 ≥ 3 的灵材，每种 ×2
```

对应位置：

- `CombatEngine.gd:82-104`
- `CombatEngine.gd:437-439`
- `TowerPanel.gd:380-385`

### 2.4 为什么第 130 层仍掉「百年朱果 ×1 + 聚灵甘露 ×2」

因为 10 层节点奖励是**静态分支**：

```gdscript
if floor_num % 10 == 0:
    百年朱果 ×1
    聚灵甘露 ×2
```

代码没有按层数、境界、妖王品阶做缩放。因此：

```text
第 10 层 = 第 20 层 = ... = 第 130 层 = 百年朱果 ×1 + 聚灵甘露 ×2
```

封顶循环结论：

- 10 层节点奖励从**第 10 层起完全封顶循环**
- 奇数 5 层节点的贡献随层数线性增长，但灵材池也封顶在「品阶 ≥ 3 的随机材料 ×2」，没有随高层提高品阶或数量

### 2.5 每日俸禄公式

```text
境界倍率 = REALM_REWARD_MULT[境界下标]
真仙圆满倍率 = 200

灵石 = 历史最高层 × 境界倍率 × 100
贡献 = max(1, round(历史最高层 × 境界倍率 × 0.5))
```

对应位置：

- `GameState.gd:2333-2360`
- `GameState.gd:50-51`

以历史最高 127 层为例：

```text
灵石 = 127 × 200 × 100 = 2,540,000
贡献 = 127 × 200 × 0.5 = 12,700
```

### 3.5 理论最高层结论

按当前满配口径（祭炼 50 重）：

```text
理论最高稳定通关：第 148 层
第 149 ~ 150 层开始无法稳定通关
```

注意：源码中祭炼没有硬上限，继续堆祭炼重数会同时提高固定值与百分比，因此若把「满重」定义为无限堆资源后的理论值，则不存在绝对有限天花板。本报告采用现有满配存档的 50 重口径。

核心瓶颈：

1. **首要瓶颈是输出不足**
   - 妖魔气血按 `1.095^层` 增长
   - 妖魔攻击按 `1.08^层` 增长
   - 玩家攻击在固定满配后不再指数增长
   - 因此 130 层后出手次数快速拉长

2. **149 ~ 150 层同时出现生存瓶颈**
   - 护符与全局减伤都接近上限
   - 单次回血 30316 已无法抵消高高层单击
   - 净伤累积超过气血池

3. **命中 / 闪避不是瓶颈**
   - 玩家实际命中率已夹到 99%
   - 敌方命中率被闪避压到约 64.8%，但仍足够造成消耗

## 4. 最不合理的 3 个点

### 1. 妖魔气血增长快于玩家输出成长

妖魔气血每层 `×1.095`，攻击每层 `×1.08`，防御每层 `×1.075`。

玩家满配后攻击基本固定，导致第 130 层以后击杀出手次数从几十次迅速膨胀到上百次。高层战斗节奏从「妖魔威胁」变成「血条拉锯」。

### 2. 里程碑奖励从第 10 层起完全封顶

第 130 层与第 10 层同样给：

```text
百年朱果 ×1
聚灵甘露 ×2
```

奇数 5 层节点的灵材池也只是「品阶 ≥ 3 随机 ×2」，没有高层专属池、数量成长或保底升阶。里程碑奖励与冲层难度严重脱节。

### 3. 首通奖励与每日俸禄数额失衡

127 层首通只有：

```text
灵石 6350
贡献 137
```

但同境界每日俸禄有：

```text
灵石 2,540,000
贡献 12,700
```

首通奖励是线性小额，俸禄却叠加境界倍率 200 与 `×100`，两者相差数百倍。冲层的即时反馈远弱于每日领取，长期激励会偏向「卡历史最高层吃俸禄」而非继续冲层。
